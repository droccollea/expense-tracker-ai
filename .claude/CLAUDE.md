This is an expense tracker app. Here are some rules that you MUST always follow for making changes to the app.

1. All features should be created on a separate git branch. The branching strategy is to create a new feature branch named like "feature-name-short-description".
2. All changes should have unit and integration test coverage.
3. All changes MUST compile and all tests MUST pass before the changes are committed.
4. All changes must be secure. Ensure any libraries introduced have no security advisories.
5. Ensure code is clean free of warnings and errors and passed a linter.
6. New should follow SOLID principles where possible.
7. Integration tests must have no errors. Where errors are encountered you will have to fix them.
8. All user inputs MUST be sanitized.
